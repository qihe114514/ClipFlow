# ClipFlow 三平台媒体预览重做设计

## 背景

当前封面点击预览只在共享 `ParseInfoCard` 中创建 `PlayerView`，视频弹窗和全屏弹窗各自创建一个 ExoPlayer。图集首项也可能被当作视频 URL 交给播放器，导致行为不正确。

本次重做覆盖抖音、小红书和 Bilibili，保留三者现有解析、下载、历史和导航流程，只替换封面预览入口和预览体验。

播放器库调研见 `docs/research/2026-08-04-player-library-research.md`。AndroidX Media3 是官方维护且近半年持续发布的方案，和现有 ExoPlayer 链路一致，因此采用官方 Media3 Compose UI，不引入新的播放内核。

## 已确认的用户行为

- 点击封面打开半屏底部抽屉，不直接进入全屏。
- 视频打开后自动播放并保留原声音。
- 视频和图集共用一个预览抽屉。
- 视频支持播放/暂停、进度拖动、音量、倍速、全屏、关闭和失败重试。
- 倍速选项为 `0.5x`、`1x`、`1.25x`、`1.5x`、`2x`。
- 按住视频画面时临时使用 `2x`，松开或手势取消后恢复按菜单选择的倍速。
- 半屏预览保持进入前的方向和系统栏，不隐藏系统栏。
- 全屏时隐藏系统栏；横向视频自动切换横屏，竖向视频保持竖屏。
- 退出全屏恢复进入全屏前的方向和系统栏状态。
- Bilibili 使用同一套预览体验；其解析和下载行为不变。

## 组件与数据流

### `ParseInfoCard`

保留封面、标题、作者、描述、统计和保存封面职责，增加可选的 `previewItems: List<ContentItem>` 参数。

- 抖音、小红书和 Bilibili 传入各自解析结果中的 `ContentItem` 列表。
- 预览入口只在封面存在且过滤后仍有可预览项时启用。
- 长按封面保存图片的既有行为保留。
- 不再在 `ParseInfoCard` 内保留小窗播放器和全屏播放器两个实现。

### `MediaPreviewSheet`

新建独立的 Compose 组件，接收可预览的 `ContentItem` 列表和关闭回调，内部负责抽屉、预览内容、控制器和全屏状态。

- 使用 `ModalBottomSheet`，首次打开为半屏状态，点击全屏后展开到最大高度。
- 预览项按原列表顺序过滤：`VIDEO`、`LIVE_VIDEO`、`IMAGE`、`LIVE_IMAGE`；`AUDIO` 不进入封面预览。
- 视频项使用同一个 ExoPlayer 实例；切换视频时先释放旧媒体，再加载新媒体。
- 图集项使用 `HorizontalPager`，保留页码指示和当前页状态。
- sheet 关闭、页面离开或组件销毁时暂停并释放播放器。

### Media3 接入

- 将 `media3-exoplayer`、`media3-common`、`media3-ui` 统一到同一版本，并加入官方 `media3-ui-compose`；若控制器插槽需要 Material 3 API，再加入对应的 `media3-ui-compose-material3`。
- 采用调研确认的稳定版本 `1.10.0`，所有 Media3 模块保持同版本。
- 使用官方 Compose video surface 作为视频画面，隐藏原生 `PlayerView` 控制器，控制栏由 ClipFlow Compose UI 绘制。
- 对官方 Compose API 集中添加必要的实验性 API opt-in，不向业务页面扩散注解。

## 交互细节

### 视频

- 自动播放，初始倍速为 `1x`，音量沿用系统当前音量。
- 点击画面显示或隐藏控制器；控制器在播放一段时间后自动淡出。
- 拖动进度条时暂停自动隐藏，松手后跳转并恢复播放状态。
- 音量按钮切换静音/恢复进入预览前的音量。
- 倍速菜单改变持久的用户选择；长按加速只改变临时播放速度，不改变菜单选择。
- 播放错误显示错误提示和重试操作，不关闭抽屉。

### 图集

- 使用图片内容的原始顺序横向浏览。
- 当前页显示页码；图片加载失败只影响当前页，并提供重新加载状态。
- 图集不创建 ExoPlayer，也不显示视频控制器。

### 全屏与方向

- 半屏状态不修改 `requestedOrientation`，不隐藏系统栏。
- 全屏按钮展开同一个 sheet 并隐藏系统栏。
- 根据当前视频宽高判断横向视频；横向视频全屏时请求横屏，竖向视频不强制改变方向。
- 进入全屏前记录方向和系统栏状态，退出全屏或关闭预览时恢复。
- 图集全屏只展开 sheet 和隐藏系统栏，不请求横屏。

## 错误处理与边界

- 无可预览项时封面不打开预览抽屉，但仍可长按保存封面。
- 视频 URL 为空、图片 URL 为空或媒体类型不匹配时不创建播放器。
- 播放器初始化、加载和播放错误统一呈现在当前预览项中，允许重试。
- 预览期间不改变解析结果、下载状态或历史记录。
- Bilibili 没有新的预览项时保持现有封面静态展示。

## 验证标准

### 自动化验证

- 添加纯逻辑测试，确保 `IMAGE`、`LIVE_IMAGE` 和 `AUDIO` 不会进入播放器，`VIDEO` 和 `LIVE_VIDEO` 才会进入播放器。
- 运行现有 JVM 测试，确认解析、导航、下载进度和 Bilibili 登录相关测试不回归。
- 运行 `git diff --check`。
- 使用仓库现有离线 Gradle 方式完成 debug 和 release 构建；若新 Media3 依赖未进入缓存，记录网络依赖阻塞，不伪造离线通过结论。

### 手工验收

- 分别验证抖音、小红书、Bilibili 视频封面点击、自动播放、声音、暂停、拖动、静音、倍速、长按 2 倍速、重试、半屏关闭和全屏退出。
- 验证三平台图集封面点击、横向翻页、页码和图片失败状态。
- 验证半屏不改变方向或系统栏，全屏横向视频切横屏，退出后恢复原状态。
- 验证 Bilibili 原有解析、分 P 和下载入口不受影响。

## 非目标

- 不替换 Media3 播放内核，不引入 libmpv 或 Compose Multiplatform 播放抽象。
- 不新增画中画、锁定控制、后台播放、缓存策略或视频下载逻辑。
- 不修改三平台解析接口、下载器、历史数据库和导航结构。
